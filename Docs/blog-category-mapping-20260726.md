# Blog category mapping (preparation — 2026-07-26)

This document maps existing blog categories to four primary commercial clusters.
**No category URLs are deleted or redirected in this release.** Redirects remain a later controlled phase after GSC review.

## Primary clusters (commercial ownership)

| Cluster | Owning commercial route | Existing category slugs (current) |
|---|---|---|
| Website Visibility | `/website-visibility-support` | `technical-seo`, `web-development` (visibility-adjacent articles) |
| CRM & Automation | `/crm-automation-support` | `ai-automation` (workflow/automation-adjacent) |
| Software Delivery | `/software-development-subscription-uk` | `software-development`, `product-development`, `legacy-modernisation`, `mobile-app-development` |
| Managed Support | `/maintenance` | `software-support` |

Cross-cutting categories such as `digital-transformation` and `business-strategy` remain educational and should not become competing commercial hubs.

## Secondary tags / subtopics (not primary indexable hubs yet)

Use these as tags or article subtopics rather than new hub pages in this release:

- AI
- Technical SEO
- Product Development
- Business Strategy
- Digital Transformation
- Analytics
- Cyber Resilience
- Web Development

## Homepage behaviour

- Large article/archive blocks are removed from the homepage DOM.
- Blog discovery uses a clean `/blog` URL (no internal UTMs).
- Category redirects are **not** implemented until traffic and relationships are reviewed.

## Next controlled phase (not in this release)

1. Review GSC impressions/clicks for each `/blog/category/*` URL.
2. Confirm which categories can safely consolidate without losing useful long-tail coverage.
3. Implement 301s only where intent and traffic justify a single destination.
4. Avoid exact-match landing pages for future SERP experiments until evidence supports them.
